AI Studio

The full prompt lifecycle in one product — specify, build, prove, release, monitor, improve — with AI automation available at every step and manual control always within reach.
Why we're building it
Prompt Studio manages prompt versions. AI Studio runs the lifecycle.

What's holding us back today

  • Checks and datasets are locked inside each prompt version and rewritten from scratch every time
  • There is no shared, explicit definition of what "good" means for a prompt
  • Production behaviour is only reachable through a report, not something you can read and act on
  • A real production failure has no path back into the test set
  • Approval checks a set of flags rather than the quality evidence itself
  • AI assistance stops at drafting a prompt

What AI Studio unlocks

  • One spec drives the prompt, its checks and its datasets together
  • Datasets and checks are reusable and improve over time instead of being recreated per version
  • AI assistance at every lifecycle step, not just authoring
  • Production traces readable in the Studio and convertible into test cases
  • The same checks run before release and keep running against live traffic afterwards
  • A visible link between prompt quality and business outcomes

The assistant
Not a feature in the product — the layer the product runs on.

What it actually does

  • Turns a rough intent into a structured spec, and asks the questions you'd have forgotten to answer
  • Writes the first draft, and explains what a revision changes and what it might break
  • Reads a failing run and says which cases failed and what they have in common
  • Proposes the check that would have caught a failure — and the cheapest one that does the job
  • Turns a production trace into a test case with the expected output filled in
  • Reviews the artefacts at commit and says what evidence is missing

Where it stops

  • It never approves, publishes, or changes anything in production
  • Everything it produces is an editable draft — no hidden state, no silent edits
  • It shows what it used to make a suggestion
  • Any step can be done by hand, and it stays out of the way
What makes it a layer rather than seven separate features: it carries context across the loop. The spec informs the checks; the production failure informs the spec edit. Its scope shapes every surface, so we need to define it early.

How we're balancing it: the new capability leads and the replacement follows only as far as that capability needs it. We never rebuild a Prompt Studio surface for parity alone, and we never ship a new capability that dead-ends because the surrounding workflow isn't there. Prompt Studio keeps running throughout, so partial replacement is fine.
Transition from Prompt Studio
Prompt Studio keeps working. People move one workflow at a time.

How the transition works

  • Both products work on the same prompts, so nobody has to move their work or start over
  • We're not rebuilding what already works — evaluation running, batch processing and the model catalog stay as they are
  • Nothing changes for the teams whose applications use our prompts
  • Each workflow stays in Prompt Studio until AI Studio genuinely does it better

Sequence

  • Retire early — the legacy library and the standalone Compare page; neither is in real use
  • Redesign, don't remove — the approval review, including relevancy plus coverage, regression and cost
  • Move carefully — the prompt editor is the busiest surface and needs parity first
  • Leave in place — batch processing and model catalog are infrastructure
Outcomes we're aiming for rather than activity targets: prompt quality, automation coverage across the lifecycle, production visibility, and gradual adoption of AI Studio.
What we propose to build first
Spec-driven prompt creation, end to end in AI Studio.
You describe what the prompt needs to do. The assistant builds the specification with you, generates the prompt from it, and generates the first checks and test data. You run it and read every output — in one place.

Why this first

  • It's already in motion — the specification and generation agent is being built
  • It's the part of the vision Prompt Studio has no answer for
  • It pulls in exactly the authoring and testing surface we need and no more — no editor parity required
  • It produces the first reusable checks and datasets, which everything later builds on

In the first slice

  • A specification built with the assistant from a plain description
  • A prompt generated from it, editable by hand at any point
  • Model, variables and output shape proposed
  • First checks and test data generated
  • Run it, and read every output

Not yet

  • Approval and publishing — those stay in Prompt Studio
  • Comparison, regression, production evaluation
To start we need to agree: that this is the first slice, which team and which prompt we build it around, and whether a specification is optional. Our proposal: optional — a prompt can exist without one, but publishing needs evaluation evidence either way.
